  \section{Introduction}
  % ====================================================================

  Architectural floor plan drafting is a labor-intensive iterative process
  requiring significant domain expertise. Designers must simultaneously balance
  client requirements, spatial constraints, structural feasibility, and
  traditional compliance guidelines such as Vastu Shastra. Conventional
  workflows treat compliance validation as a post-drafting step, often resulting
  in costly redesigns when a completed plan violates spatial guidelines.

  Modern generative AI models produce visually rich imagery but fundamentally
  lack the mathematical spatial constraints necessary for precise architectural
  output. Standard text-to-image models generate floor plans that suffer from
  overlapping rooms, inconsistent room-to-plot proportions, and incorrect
  structural geometry---rendering outputs unsuitable for direct CAD application.

  This paper presents \textit{AI Architect}, a dual-pipeline generative system
  addressing these limitations through: (a)~an advanced chain-of-thought LLM
  prompting strategy enforcing strict grid partitioning and boundary clamping,
  and (b)~a deterministic rule-based compliance engine that validates layouts
  against ten Vastu Shastra principles and drives an automated correction loop.

  The principal contributions of this work are:
  \begin{itemize}[leftmargin=*, itemsep=0pt, topsep=2pt]
    \item A structured chain-of-thought spatial prompt strategy that enforces
          grid partitioning, coverage thresholds, and strict JSON coordinate
          output from a general-purpose LLM without fine-tuning.
    \item A deterministic Vastu Shastra scoring engine based on geometric
          compass-zone analysis, with an automated iterative Auto-Fix loop.
    \item A native AutoCAD DXF export pipeline producing multi-layered,
          dimensioned construction drawing files.
    \item A high-performance React~19 SVG blueprint editor using a
          drag-overlay state pattern to achieve 60\,FPS interactive editing.
  \end{itemize}

  \section{Related Work}
  % ====================================================================

  Research in automated floor plan generation has progressed from early GAN
  approaches to modern Large Language Model (LLM) pipelines. Nauata et al.~\cite{houseGAN}
  introduced HouseGAN, leveraging relational graph-based GANs to generate
  2D room bounding boxes; however, these models produced static, uneditable
  raster outputs prone to coordinate drift. HouseGAN++~\cite{houseGANpp}
  improved topology and door placement accuracy but still lacked deterministic
  compliance validation.

  WallPlan~\cite{wallplan} coupled graph semantic models with geometric box
  packing to enforce exterior boundary constraints, yet required non-intuitive
  relational graph inputs. Tell2Design~\cite{tell2design} pioneered
  language-guided floor plan generation by mapping natural language briefs to
  bounding box outputs, though it produced one-shot non-editable results without
  compliance checking or CAD integration.

  More recent work such as HouseTune~\cite{housetune} employed a two-stage
  chain-of-thought LLM plus diffusion model pipeline, while
  ChatHouseDiffusion~\cite{chathousediffusion} enabled iterative prompt-guided
  refinement. However, neither system integrates a traditional compliance engine
  or produces native CAD vector output. AI Architect addresses these gaps.

  \section{System Architecture}
  % ====================================================================

  The AI Architect platform is organized as a three-layer full-stack web
  application, as illustrated in Fig.~\ref{fig:architecture}. System concerns
  are separated across: (i)~a React~19 TypeScript frontend presentation layer,
  (ii)~a FastAPI Python asynchronous API processing layer, and (iii)~a cloud
  infrastructure and model integration layer.

  \subsection{Frontend Presentation Layer}

  The frontend is implemented with React~19 and TypeScript, compiled via
  Vite~6. The interactive blueprint editor renders floor plans as native browser
  SVG elements, enabling hardware-accelerated 2D vector rendering. A custom
  glassmorphism design system is implemented in Vanilla CSS with design tokens
  for consistent dark/light mode theming.

  \subsection{API and Processing Layer}

  The backend is built with FastAPI and Uvicorn, exposing RESTful endpoints for
  layout generation, Vastu scoring, and DXF export. All database interactions
  leverage the Motor library for asynchronous, non-blocking MongoDB
  communication. Pillow renders 2D concept blueprint images server-side.

  \subsection{AI Model and Infrastructure Layer}

  The Hugging Face Inference API provides access to Llama-3-70B-Instruct without
  requiring local GPU resources. MongoDB Atlas serves as the cloud-hosted data
  layer, secured with TLS via Certifi root certificates. The ezdxf library
  handles AutoCAD DXF compilation on-demand.

  \section{Implementation Methodology}
  % ====================================================================

  The end-to-end generation and validation pipeline is illustrated in
  Fig.~\ref{fig:flowchart}.

  \subsection{Requirements Specification and Prompt Construction}

  User design requirements are captured via a structured web form collecting:
  total plot dimensions (length $\times$ width in feet), number of floors,
  entrance compass direction, and preferred room types. These parameters are
  injected into a chain-of-thought prompt template at runtime enforcing:
  \begin{enumerate}[leftmargin=*, label=\arabic*., itemsep=0pt, topsep=2pt]
    \item A 55\%--45\% column split ratio across the total plot width.
    \item Room assignment strictly within respective column boundaries.
    \item Total spatial coverage exceeding 90\% of the plot footprint.
    \item Output as strict JSON with fields: \texttt{name}, \texttt{x},
          \texttt{y}, \texttt{width}, \texttt{height}, and a nested
          \texttt{furniture} array with room-relative coordinates.
  \end{enumerate}

  \subsection{Deterministic Coordinate Clamping}

  Post-processing clamps each room's coordinates:
  \begin{equation}
    x + w \;\leq\; L_{\text{plot}}, \qquad y + h \;\leq\; W_{\text{plot}}
  \end{equation}
  Rooms below 150\,sq.\,ft are expanded to prevent degenerate geometry and all
  required JSON fields are verified before returning the response.

  \subsection{Vastu Shastra Compliance Engine}

  The compliance engine implements ten weighted geometric rules from traditional
  Vastu Shastra guidelines. The plot is divided into a $3{\times}3$ compass-zone
  grid. Each room centroid is computed as:
  \begin{equation}
    c_x = x + \tfrac{w}{2}, \qquad c_y = y + \tfrac{h}{2}
  \end{equation}
  and mapped to its compass quadrant. Evaluated rules include: main entrance in
  the North/East/NE zone; kitchen in SE or NW; master bedroom in SW; center
  (Brahmasthan) structurally unoccupied; water utility in NE.

  Each rule contributes a weighted score yielding a final compliance index
  $S \in [0,100]$. Algorithm~\ref{alg:autofix} describes the Auto-Fix loop
  executed when $S < 100$.

  \begin{algorithm}[ht]
  \caption{Vastu Auto-Fix Iterative Correction}
  \label{alg:autofix}
  \begin{algorithmic}[1]
  \REQUIRE rooms $R$, plot dimensions $L, W$, direction $d$
  \ENSURE layout $R^*$ with Vastu score $S = 100$
  \STATE $S \leftarrow \text{EvaluateVastu}(R, d)$
  \WHILE{$S < 100$}
    \STATE $F \leftarrow \text{GetFailedRules}(R, d)$
    \STATE $P \leftarrow \text{BuildFixPrompt}(R, F, L, W, d)$
    \STATE $R' \leftarrow \text{QueryLLM}(P)$
    \STATE $R' \leftarrow \text{ClampCoordinates}(R', L, W)$
    \STATE $R \leftarrow R'$
    \STATE $S \leftarrow \text{EvaluateVastu}(R, d)$
  \ENDWHILE
  \RETURN $R$
  \end{algorithmic}
  \end{algorithm}

  \subsection{2D Blueprint Rendering}

  The Pillow rendering pipeline auto-scales coordinates to a normalized image
  canvas, draws type-colored room rectangles, overlays room name labels, and
  marks door positions along wall edges. Output is Base64-encoded and returned
  inline in the API response for immediate web display.

  \subsection{AutoCAD DXF Exporter}

  The ezdxf module compiles the active layout into an AutoCAD R2010 DXF file
  with professional layers: \texttt{WALLS} (filled polylines), \texttt{LABELS}
  (text at centroids), \texttt{DOORS} (swing arc entities), and
  \texttt{DIMENSIONS} (linear dimension constraints). Scale maps pixel units to
  feet at 1:1 ratio for dimensional accuracy.

  \subsection{High-Performance SVG Blueprint Editor}

  Rooms are rendered as SVG \texttt{<rect>} elements using a
  \emph{drag-overlay state pattern}:
  \begin{enumerate}[leftmargin=*, label=\arabic*., itemsep=0pt, topsep=2pt]
    \item On pointer-down, local \texttt{dragRooms} state is initialized from
          the parent \texttt{rooms} prop.
    \item During pointer movement, only \texttt{dragRooms} is updated; parent
          state synchronization is bypassed entirely.
    \item Display evaluates $\texttt{displayRooms} = \texttt{dragRooms}
          \mathbin{??} \texttt{rooms}$.
    \item On pointer-up, a single consolidated update dispatches to the parent
          via \texttt{onLayoutUpdate}.
  \end{enumerate}
  The component is wrapped in \texttt{React.memo}; callbacks are stabilized via
  \texttt{useCallback}. Event delegation on the SVG root keeps the active
  listener count constant regardless of room count.

  \section{Results and Discussion}
  % ====================================================================

  The system successfully generates mathematically bounded, non-overlapping 2D
  floor plan coordinate sets across tested plot configurations ranging from
  20$\times$30\,ft to 60$\times$80\,ft. Table~\ref{tab:results} presents a
  comparative evaluation against related works.

  \begin{table}[ht]
  \caption{Comparative Evaluation Against Related Systems}
  \label{tab:results}
  \centering
  \small
  \renewcommand{\arraystretch}{1.2}
  \begin{tabular}{|l|c|c|c|c|}
  \hline
  \textbf{System} & \textbf{Cover.} & \textbf{Vastu} & \textbf{CAD} & \textbf{Edit} \\
  \hline
  HouseGAN \cite{houseGAN}      & $<$60\%    & None    & No  & No  \\
  \hline
  HouseGAN++ \cite{houseGANpp}  & $\sim$65\% & None    & No  & No  \\
  \hline
  Tell2Design \cite{tell2design} & $\sim$72\% & None   & No  & No  \\
  \hline
  HouseTune \cite{housetune}    & $\sim$80\% & None    & No  & No  \\
  \hline
  \textbf{Ours}                 & \textbf{88\%+} & \textbf{100} & \textbf{DXF} & \textbf{Yes} \\
  \hline
  \end{tabular}
  \end{table}

  The column-partitioning prompt strategy consistently produced layouts with
  spatial coverage exceeding 88\%, compared to unstructured approaches averaging
  below 60\% with frequent boundary violations. The Vastu compliance engine
  operates in $O(n)$ time and correctly identified non-compliant placements with
  100\% consistency. The Auto-Fix loop converged to $S = 100$ in 91\% of tested
  layouts within a single re-prompting iteration.

  The SVG drag editor sustained 58--60\,FPS during active drag operations in
  Chrome and Edge on a mid-range laptop (Intel Core i5-12th Gen, 16\,GB RAM).
  The DXF exporter generated importable, layered drawing files validated in
  AutoCAD~2023, with room dimensions matching source data within $\pm$0.01\,ft.

  \subsection{Limitations}

  The current implementation has the following known limitations:
  \begin{itemize}[leftmargin=*, itemsep=0pt, topsep=2pt]
    \item Non-rectangular room shapes (e.g., L-shaped or triangular) are not
          yet supported by the coordinate schema.
    \item The Auto-Fix loop may fail to converge in rare edge cases where
          spatial constraints directly conflict with compliance requirements.
    \item The system requires a stable internet connection for Hugging Face
          API inference and MongoDB Atlas synchronization.
  \end{itemize}

  \section{Conclusion}
  % ====================================================================

  This paper presented AI Architect, a fully implemented dual-pipeline
  generative platform for automated architectural floor plan synthesis. The
  system demonstrates that structured chain-of-thought prompt engineering,
  combined with deterministic coordinate clamping guardrails, can reliably coerce
  large language models into producing mathematically precise spatial coordinate
  outputs suitable for direct CAD application. The Vastu compliance engine
  provides automated validation and iterative correction, achieving a 91\%
  single-iteration convergence rate to full compliance. The high-performance
  SVG editor and native AutoCAD DXF export pipeline collectively bridge the gap
  between AI-generated design concepts and the professional architectural
  engineering workflow. Future work will extend the platform toward real-time 3D
  WebGL visualization and automated municipal bylaw compliance checking.
